PART 01 · 一眼看懂

这个示例，到底做了什么？

一句话：它在电脑里完整复现了一枚雷达制导导弹——从开机搜索目标、锁定目标，到最后命中目标的全过程。

这不是一个玩具演示。弹体模型出自多篇控制领域经典论文，是学术界与工程界反复使用的基准对象；仿真结果里，导弹的脱靶量只有 0.265 米。

PART 01 · 一眼看懂

把它想象成一只捕猎的猎鹰

导弹的每个部分，都对应猎鹰身上的一个"器官"——

眼睛导引头 Seeker
装在万向节上的雷达天线，始终盯着目标。关键不是"猎物在哪"，而是感知"视线正在往哪个方向转"。
直觉制导律 Guidance
捕猎本能：让视线转动趋于停止，两头必然相撞。它把"怎么追"翻译成一句话——需要多大的横向加速度。
脊髓自动驾驶仪 Autopilot
大脑说"往左使劲"，脊髓负责精确执行：控制舵面，让弹体转弯不欠火候、也不过头。
身体弹体 Airframe
翅膀与躯体。气动力、推力、重力共同决定它怎么飞，且随速度和姿态非线性变化。

PART 03 · 深入子系统 · 2/10

国际标准大气：
一切计算的起点

空气密度、温度、声速都随高度变化，直接决定气动力大小。模型实现了国际标准大气（ISA）的两段式近似：

对流层（0–11 km）温度随高度线性下降，每升高 1 km 约降 6.5 ℃；平流层下部（11–20 km）温度恒定（约 −56.5 ℃），空气继续变稀薄。

PART 03 · 深入子系统 · 3/10

气动力与运动方程：导弹的"物理引擎"

根据当前的马赫数、迎角和舵偏查出气动力系数，算出轴向力、法向力和俯仰力矩，再积分运动方程，得到位置、速度与姿态。

PART 03 · 深入子系统 · 4/10

非线性怎么办？
查表 + 插值

气动力系数并非常数，而是以二维数据表存储：横轴马赫数（2 → 4，步长 0.5），纵轴迎角（−20° → +20°，步长 1°）。

仿真运行到任一状态，就用 2-D Lookup Table 模块实时插值出当前系数——这是处理非线性气动特性的标准工程手段。

PART 03 · 深入子系统 · 5/10

三环路自动驾驶仪：让弹体"听话"

任务：接收制导律下发的法向过载指令，并精确实现它。三个环路层层递进：

LOOP 1
舵偏内环

保证舵面快速、准确偏转。

→
LOOP 2
阻尼环

速率陀螺反馈角速度，增阻尼、抑振荡。

→
LOOP 3
过载外环

加速度计测实际过载，消除静差。

从 2 马赫到 4 马赫，弹体响应特性变化剧烈——一套固定参数不可能全程适用。解决办法是增益调度：增益存入查找表，飞行中按迎角 × 马赫数实时切换，并配合抗积分饱和防止舵面限幅时积分器"憋坏"。

PART 03 · 深入子系统 · 6/10

设计之前，先"侦察"弹体

经典控制设计的第一步：在多个配平飞行条件下把非线性模型线性化，得到一组线性模型，分析其开环频率特性。

MATLAB 可自动完成配平与线性化，再用 Control System Toolbox 可视化弹体的频率响应——设计增益前先看清"脾气"。

PART 03 · 深入子系统 · 7/10

导引头：导弹的"眼睛"与"前庭"

既要盯住目标（驱动万向节天线），又要给出视线角速率估计。内部两个回路协同：

跟踪环 Tracking Loop

让天线始终对准目标。时间常数 tors = 0.05 s——快了噪声大、慢了跟不上，典型的工程折中。

稳定环 Stabilization Loop

弹体自己在颠簸，稳定环用速率陀螺抵消弹体转动的影响，让"视线"稳稳指向目标。

PART 03 · 深入子系统 · 8/10

Stateflow 状态机：作战指挥官

什么时候搜索、什么时候攻击？Guidance 子系统内嵌的 Stateflow 状态机，
管理着三个作战阶段：

STAGE 1
搜索 Target_Search

状态机直接控制万向节按预设规律摆动，在空域中扫描目标。

→
STAGE 2
捕获 Acquire

目标进入 10° 雷达波束内，标记"已捕获"，短暂延迟确认。

→
STAGE 3
闭环制导 Guided

比例导引接管控制权，导弹直奔预测交会点。

模式切换由 Simulink 事件或图内部事件触发；状态机还定义了丢失锁定、未捕获到目标等异常情形的降级逻辑。

PART 03 · 深入子系统 · 10/10

真实世界的"不完美"：
天线罩像差

雷达天线罩会折射回波信号，让导引头读出一个略有偏差的目标视角——这是一种典型的寄生反馈，可能损害精度甚至导致不稳定。

模型用增益 K_r = −0.02 的线性关系近似这一非线性效应，用于检验系统鲁棒性。

把不完美建模出来，正是这个示例的价值之一——你还可以加入陀螺过载敏感性等效应，检验跟踪器与滤波器的稳健性。
PART 04 · 核心原理

比例导引（PNG）：70 年不衰的"灵魂算法"

ac  =  N · Vc · λ̇
（ac 过载指令 · N 导航比 · Vc 接近速度 · λ̇ 视线角速率）

直觉表述：两个匀速运动的物体，只要视线方向保持不变（视线角速率 λ̇ = 0），就必然相遇。所以一旦发现视线在转动，就施加一个与视线角速率成正比的过载去"掰直"它。

为什么说它优雅？不需要解算精确拦截点、不需要目标机动信息、对雷达/红外/电视制导通吃——只用一个乘法完成"预测 + 修正"。简洁、鲁棒、久经实战。
PART 04 · 核心原理

实现它，只需要两样信息

都由导引头提供——

① 接近速度Vc · Closing Velocity
导弹与目标距离缩短的快慢。雷达制导导弹用多普勒跟踪直接测得——回波频移正比于接近速度。
② 视线角速率λ̇ · Sightline Rate
视线方向转动的快慢。由跟踪环 + 稳定环 + 估计滤波器共同估计，是导引头最关键的输出。

PART 06 · 参数与词典 · 4/5

术语小词典（上）

法向过载
垂直于弹轴方向的加速度，以 g 为单位。导弹不直接"控制轨迹"，而是控制过载——轨迹是过载积分的结果。
迎角（Alpha）
弹轴与来流方向的夹角，升力与阻力都由它驱动。本例工作范围 ±20°。
马赫数（Mach）
速度与当地声速之比。声速随高度（温度）变化，同一速度在不同高度的马赫数不同。
配平与线性化
在定直平飞等"平衡点"上求出舵偏/迎角组合，把非线性模型近似为线性模型——经典控制设计的起点。
增益调度
按飞行状态（迎角 × 马赫数）实时切换控制器参数，用一组局部线性设计覆盖全飞行包线。

抗积分饱和
舵面有 ±30° 限幅；指令超限时防止积分器继续累积，否则退饱和时会产生大超调。
视线角速率 λ̇
导弹—目标连线方向的变化速率，比例导引的核心输入，由导引头估计给出。

寄生反馈

专题 A · 模块协作 · 1/5

信号的旅程（上）：从目标到指令

把一个知识点看作一次"接力"：每个模块只做一件事，然后把结果交给下一个。跟随信号的脚步，先走前半程——三次交接，把"看见"变成"指令"：

① 接收导引头
目标反射的雷达波打在导引头天线上，天线由万向节驱动，始终保持指向目标。
② 感知跟踪器
跟踪环 + 稳定环把天线运动和弹体转动折算合并，输出最关键的度量——视线角速率 λ̇。
③ 决策制导律
比例导引只做一个乘法：ac = N·Vc·λ̇，产出"过载指令 Az_d"交给自动驾驶仪。
专题 A · 模块协作 · 2/5

信号的旅程（下）：从指令到命中

下半程的三次交接：指令变成动作，动作变成机动，机动又改变下一次的"看见"——

④ 执行自动驾驶仪 → 舵机
三环路把过载指令换算成舵偏指令，舵机以最高 500°/s 的速率偏转舵面，最大 ±30°。
⑤ 运动弹体
舵面改变气动力 → 弹体获得法向过载 → 位置、速度、姿态随之变化——导弹开始转弯。
⑥ 反馈几何
导弹和目标的相对位置变了 → 视线方向跟着变 → 导引头在下一步重新测量 λ̇。循环往复，直到命中。
走完 ⑥ 就回到 ①：相对位置变了，视线角速率 λ̇ 跟着变——每 0.01 秒一圈，循环往复，直到命中。下一页看这个圈里套着的环。
专题 A · 模块协作 · 3/5

嵌套的环：谁快、谁慢

整条回路其实是一层套一层的多个闭环。工程铁律：越靠内的环，响应必须越快——外环发出指令，内环要能跟得上，系统才能稳定。

最内 · 舵机环
舵机二阶模型，带宽 150 rad/s、阻尼 0.7。它负责最快地"转舵"，是所有环的地基。
次内 · 阻尼环
速率陀螺测量俯仰角速度 q 并反馈，抑制弹体振荡。陀螺带宽 100 Hz，稳定环增益 Ks 取带宽的 1/5。
中层 · 过载环
加速度计测实际过载 az 并跟踪指令。自动驾驶仪的带宽决定了它能响应多快的指令。
最外 · 制导环
整条寻的回路最慢：跟踪环时间常数 0.05 s，估计滤波器带宽 7 rad/s（约为自动驾驶仪带宽的一半），噪声滤得越干净，制导越平顺。
反过来想：如果自动驾驶仪带宽比舵机还高，舵机跟不上指令，整个内环先抖起来；如果制导环比自动驾驶仪还快，噪声会直接灌进弹体。逐层递减的带宽，就是这套系统的"速度秩序"。

专题 B · 模块细节 · 1/3

气动系数：表格背后的真实公式

第 10 页的二维表不是凭空来的——它的每一格都由初始化脚本 aero_guid_dat.m 中的公式生成：

法向力系数与迎角、马赫有关
迎角的三次项表示：迎角越大，升力增长越慢（气流失速），这是非线性气动特性最直接的体现。
Czα = a·α³ + b·α|α| + c·(2 − M/3)·α
俯仰力矩系数决定静态稳定性

专题 B · 模块细节 · 2/3

视线角速率：两路信号合出来的

整个制导系统最关键的度量，不能直接量出来，只能估计——因为它受弹体自身转动的污染：

问题弹体在转，天线也在转
天线角速度是"弹体转动 + 真实视线转动"的混合。如果直接当真，制导律会把弹体自己的抖动当成目标机动，越追越乱。
解法①稳定环
稳定环用速率陀螺测量弹体转动，把天线指向惯性空间稳下来——先把"弹体抖动"这一路抵消掉。
解法②合成与滤波
视线角速率 = 陀螺测得的天线角速率 + 接收机测得的跟踪误差变化率，两者求和后经低通滤波输出平滑估计。
配比带宽的折中
滤波器带宽取 7 rad/s = 自动驾驶仪带宽的一半——滤得太宽噪声钻进来，滤得太窄延迟害了制导律。取半是经典经验值。
专题 B · 模块细节 · 3/3

寄生反馈：最危险的"悄悄话"

天线罩像差这类效应，可怕在它偷偷把输出喂回输入，形成本不该存在的第三条回路：

来源物理上不可避免
天线罩的曲面让回波发生折射，导引头读到的视角与真实视角有偏差，而且偏差随天线转角变化。
危害虚假信号闭环
视角偏差 → 制导律以为目标在动 → 发出多余的过载指令 → 弹体转弯 → 视线又变 → 偏差继续放大。正反馈的雪球，可能振荡甚至失稳。
建模一页纸的近似
用增益 Kr = −0.02 把"万向节角 → 视角误差"近似为线性关系，塞进跟踪环里参与仿真。
它存在的意义：工程上第一版设计往往"太干净"。把像差、陀螺过载敏感性等不完美装进模型，才能检验跟踪器与滤波器是否真的鲁棒——这也是本示例的教学价值所在。
专题 C · Stateflow 状态机详解 · 1/5

Stateflow：给导弹装上"大脑皮层的状态"

Simulink 擅长描述"连续的信号流"；但"现在该搜索还是该攻击"是离散的状态——这正是 Stateflow 的舞台。

状态 vs 流程一个本质区别
流程按顺序走完就结束；状态是"停留并等待"——只要不满足离开条件，就一直守在这个状态里做事。
事件驱动谁来扳动开关
状态之间的转换由事件或条件触发，例如"目标进入波束"→ 捕获事件。事件可以从 Simulink 传进来，也可以在图内部产生。
本模型的图表100 Hz 的指挥官
Guidance 子系统中的状态图名为 Guidance Processor (Updated @100Hz)，它每 0.01 秒被唤醒一次，检查事件、更新模式、下发新指令。
一图两用制导 + 引信
图中同时管理着两件事：制导状态机（搜索/捕获/制导）与引信状态机（待机/解锁）——下一页开始逐个拆开看。
专题 C · Stateflow 状态机详解 · 2/5

制导状态机：四个状态一次讲清

仿真的 3.46 秒里，状态机完整经历了一轮循环——表里每一行，都是"画面里真实发生过的事"：

状态在做什么何时离开
Target_Search
搜索		直接控制万向节按规律扫描（Sigma 指令），在空域里"找"目标目标进入波束 → 捕获事件发起（本例 0.69 s）
Target_Look
凝视		短暂确认：目标已被稳定跟踪；引信仍处 Inert（未解锁）确认完成 → 进入闭环制导
Guided
闭环制导		启用比例导引，向下游发过载指令；同时通知引信"可以解锁了"命中（3.46 s）或丢失锁定/中止

中止		放弃当前攻击：停止制导指令，系统进入安全状态人为干预或按失效逻辑复位

专题 C · Stateflow 状态机详解 · 3/5

事件与模式：状态机怎么"听到"外界

两条听觉通路Simulink ↔ Stateflow
事件可以从 Simulink 模块（如比较器检测到"目标进波束"）触发转换，也可以在 图内部由状态逻辑自己产生（如定时确认后自触发）。双向都能传。
Acquire捕获事件
跟踪器在目标进入 10° 波束宽度内时拉起目标捕获标记，作为事件喂给状态机，触发 Search → Look 的切换。
Mode模式信号
状态机把当前模式通过 Mode 信号广播给整个模型；各子系统按模式切换行为——例如搜索时不启用制导律，闭环后才允许大过载机动。
100 Hz 步进离散与连续的桥梁
连续仿真中，状态图每 0.01 s 被采样一次：检查事件、判定条件、更新输出。频率足够高，模式切换对整体回路"几乎无感"，但逻辑却清晰可控。
为什么值得用状态机？所有作战模式、所有异常路径一笔一画可见、可仿真、可测试——比埋在 if-else 脚本里强得多。
专题 C · Stateflow 状态机详解 · 4/5

引信状态机：两条命的保险丝

为什么搜索阶段不解除保险？因为那时候根本不该爆炸——这是真实导弹的安全设计，模型里也原样保留了：

Inert 待机出厂状态
战斗部处于保险状态，即使误触发也不会起爆。搜索、凝视阶段一直待机——此时目标可能只是杂波。
Armed 解锁只在闭环制导后
状态机进入 Guided（闭环制导真正启动）时，才允许切到 Armed——此时导弹已确凿锁定目标，错过即失去机会。
安全的哲学与作战状态联动
保险不是独立逻辑，而是制导状态的下游：攻击未确认 → 绝不解锁。这套"状态驱动安全"的写法，在真实弹上沿用了数十年。

专题 C · Stateflow 状态机详解 · 5/5

异常处理：打不中目标怎么办

官方文档特意点明：状态机的价值就在于"能快速定义全部作战模式"——包括失败路径。模型里预演了这些情况：

丢失锁定Loss of Lock
跟踪中目标突然从波束消失（机动逃逸 / 电子干扰）——状态机定义好降级动作：先重新搜索，搜不到就进入中止路径。
搜索失败时间耗尽
搜索持续超时仍未捕获目标——不能无限扫下去，按预置逻辑处理超时，避免带着错误目标进入攻击。
中止与复位全身而退
Abort 状态把系统带回安全态：停止制导指令、引信回到 Inert——即使脱靶，也要让导弹"可预测"地结束飞行。
这就是"模式思维"的力量：把正常、异常、边界全部显式建模，一共也就十几个状态——复杂系统里最难管的"边角情况"，在状态图里一目了然。
